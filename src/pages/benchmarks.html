Where Pelago is slower

Pelago is not faster than C everywhere, and the table shows every row. Against gcc -O2 the largest gaps are structlist (2.20×), bintrees (2.07×), matmul (1.84×), mapwork (1.76×), knucleotide (1.57×) and resultpath (1.56×). Against Rust the largest are structlist (1.64×), collatz (1.56×), levenshtein (1.44×) and knucleotide (1.43×). Others are slower by a third or less: fib38, blur, lru, nbody, mandelbrot, fannkuch and kostya_bf_bench.

Two rows need context. bintrees is 7.6× slower than a hand-tuned C++ variant that allocates from an arena (3.8 ms against Pelago's 29 ms), and levenshtein is 1.5× slower than clang -O2 (0.133 s against 0.200 s) even though it ties gcc -O2. The table compares against gcc -O2 as published; the full per-compiler numbers are in the run linked below.

How to read this

  • Same behaviour, not same rules. Pelago traps on integer overflow. The C and Rust builds above do not check, so they do less work. The same run also builds C with -ftrapv and Rust with overflow checks on. Against those, Pelago's geometric mean is {{bench:geomean_trapv}}× of gcc -ftrapv and {{bench:geomean_rust_checked}}× of checked Rust.
  • Small programs. Most run for a few to a few hundred milliseconds. They test the code generator, not whole applications, and a few percent either way is not a result.
  • Output is checked. Every program prints the same output as its C twin, or the harness reports a mismatch.
  • The programs are ours. Some follow the public problem descriptions of well-known suites (such as kostya and bddicken). They are rewrites, not the original sources, and each has C, C++, Rust and Pelago versions in the compiler repository.
  • Other CPUs. The same run also measured AArch64 (Linux on GitHub's and Blacksmith's ARM runners). Those results are in the run's artifacts but are not summarised on this page yet, so no ARM figure is claimed here. The x86-64 backend has had the most tuning.
  • Small and register-poor targets. The harness does not yet measure microcontroller-class hardware or a register-limited code generator, so this page makes no claim about them.

Binary size

Pelago writes executables directly, with no linker and no C library, so they are small: between 2 and 19 KiB here, against 16 to 20 KiB for gcc -O2 and about 4.4 MiB for rustc -O. tcc, the small C compiler, still produces smaller files than Pelago on 31 of the 41 programs (typically 3 to 6 KiB against Pelago's 5 to 12). Closing that gap is a goal; it is not reached.

Run it yourself from a checkout of the compiler (needs gcc and Python 3; the other compilers add their columns):

python3 bench/harness/run.py --runs 5 --size medium

The sources of every benchmark, with their C, C++ and Rust twins, are in bench in the compiler repository, and the workflow is bench-harness under its Actions tab.
