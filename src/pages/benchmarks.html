Benchmarks

Native Pelago against C (gcc -O2) and Rust (rustc -O) on eleven small programs. Pelago is at or below C on {{bench:at_or_below_c}} of {{bench:rows_n}}, with a geometric mean of {{bench:geomean_c}}× of C's time. Shorter bars are faster.

{{bench}}

How to read this

  • Same behaviour, not same rules. Pelago traps on integer overflow. The C and Rust builds above do not check, so they are doing less work. The suite also has a --checked mode that compares against C with -ftrapv and Rust with overflow checks on.
  • Where Pelago loses. fib38 (deep recursion) is slower than C, and mapwork is a tie. Other programs are within a few percent, which on a shared machine is noise.
  • Small programs. Most run for 5 to 150 ms. They test the code generator, not whole applications, and a few percent either way is not a result.
  • Other CPUs. The AArch64 backend is slower than C so far: the geometric mean on GitHub's ARM runners was about 1.4× to 1.7× of C -O2 on Linux, macOS and Windows (2026-10-21). x86-64 has had most of the tuning.
  • Output is checked. Every program prints the same output as its C twin, or the script reports a mismatch.

Run it yourself from a checkout of the compiler (needs gcc and Python 3; rustc adds the Rust columns):

sh compiler/benches/compare.sh --runs 7
sh compiler/benches/compare.sh --checked --runs 7

On Windows use Git Bash. The sources of every benchmark, with their C and Rust twins, are in compiler/benches.
