Шаблоны, которые заглядывают внутрь списка, массива или среза. Они сочетаются со всем из `switch.md`: ветвями
`switch`, `is` в условиях, `guard ... else`, охранными условиями с `if`, альтернативами и `name is pattern`.

## 1. Формы [#1-the-shapes]

```
switch xs {
    case []:                       "empty"
    case [x]:                      "one: #x"
    case [a, b]:                   "two: #a and #b"
    case [first, ...rest]:         "#first, then #(rest.len()) more"
}
```

| Шаблон | Соответствует |
|---|---|
| `[]` | списку без элементов |
| `[a, b]` | ровно двум элементам, связанным с `a` и `b` |
| `[a, ...rest]` | одному или более; `rest` — всё после `a` (возможно, пусто) |
| `[...init, last]` | одному или более; `init` — всё перед `last` |
| `[first, ...mid, last]` | двум или более, середина связывается с `mid` |
| `[first, ...]` | одному или более; остаток игнорируется (голое `...`) |
| `[0, x]`, `[.circle(r), ...]` | элементы могут быть любым шаблоном: литералами, диапазонами, вариантами enum, вложенными списками |

- **Маркер остатка — `...`**, тот же символ, что и распаковка (spread) в `[0, ...xs, 99]`: в выражении он
  раскладывает элементы наружу, в шаблоне — собирает элементы внутрь. Шаблоны структур сохраняют `..` для
  «игнорировать остальные поля»; они различаются, потому что у остатка списка есть длина и обычно имя.
- Не более одного маркера остатка в шаблоне.
- Работает с `[T]`, `[T; N]` и представлениями-срезами. У массива фиксированного размера длина известна, поэтому
  `[a, b]` для `[int; 2]` всегда подходит, и компилятор это знает.

## 2. Остаток — это представление [#2-the-rest-is-a-view]

`rest` — это **представление-срез** (collections.md, раздел 2), а не новый список. Поэтому его создание ничего не
стоит (указатель и длина) и, как любое представление, оно живёт столько же, сколько ветвь, и его нельзя
сохранить или вернуть. Чтобы сохранить: `copy rest`.

```
fn sum(xs: [int]) -> int {
    switch xs {
        case []:             0
        case [h, ...t]:      h + sum(t)          // t is a view; passing it down is fine
    }
}

fn count(xs: [int], acc: int) -> int {
    switch xs {
        case []:             acc
        case [_, ...t]:      become count(t, acc + 1)    // guaranteed tail call
    }
}
```

## 3. Режимы доступа [#3-access-modes]

Режимы работают на привязках, как и везде. Режим пишется перед привязкой, к которой он относится:

```
switch inout xs {
    case [inout first, ...inout rest]:
        first += 1                  // changes xs[0] in place
        rest.reverse!()             // changes the rest in place
    case []: ...
}
```

- По умолчанию доступ только для чтения (`let`). `inout` требует, чтобы проверяемое выражение тоже было `inout`.
- **`sink` для элементов не разрешён**: изъятие одного элемента из списка оставило бы дыру. Чтобы разобрать
  список целиком, используйте методы вроде `pop`/`remove` или будущий шаблон списка с `sink` (раздел 7).

## 4. Где они работают [#4-where-they-work]

```
if args is [cmd, ...rest] { run(cmd, rest) }

guard args is [path] else { return err(usage()) }       // path is usable after the guard

switch line.split(" ").to_list() {
    case ["add", name]:            add!(name)
    case ["remove", name]:         remove!(name)
    case ["list"]:                 list()
    case ["rename", old, new]:     rename!(old, new)
    case [cmd, ...]:               print("unknown command #cmd")
    case []:                       print("empty line")
}
```

- **Исчерпывающность:** компилятор отслеживает длины. `[]` плюс `[_, ...]` — полный набор; так же `[]`, `[_]`,
  `[_, _, ...]`. Недостающие длины названы в сообщении об ошибке.
- **Объявления не должны завершаться неудачей.** `const [a, b] = xs` принимается, только если `xs` — массив
  фиксированного размера с такой длиной (`[int; 2]`). Для списка используйте `guard xs is [a, b] else { ... }`
  или `if xs is`.
- Альтернативы работают, если они связывают одни и те же имена: `case [x], [x, _]:`.
- `name is pattern` работает: `case whole is [first, ...]:` сохраняет и список, и его первый элемент.
- **Текст поддерживает оба варианта**: литеральные случаи и шаблоны списков (LP7). Для `string` или `str`
  элементами являются `char`, а остаток — представление `str`: `case ['a', ...rest]:` или `case [c, ...]:`.
  Литералы остаются простым способом проверить значение целиком (`case "add":`). Длины считаются в символах,
  поэтому проверка длины один раз проходит по тексту; сопоставление с начала никогда не декодирует больше, чем
  нужно шаблону.

## 5. Закрытие вопроса о построителях (B5) [#5-closing-the-builder-question-b5]

Построителям нужен был способ пропускать неподходящие элементы. `is` уже связывает имена, поэтому новый
синтаксис не нужен. Фильтр, записанный через `is`, делает свои имена доступными результату:

```
const radii = [s of shapes if s is .circle(r) ~> r]                  // only circles
const firsts = [x of rows if x is [first, ...] ~> first]             // rows that are not empty
const values = [o of opts if o is some(v) ~> v * 2]                  // some options only
```

(Присутствующий вариант `option` — это `some(v)`; см. решения ниже.)

## 6. Почему не другие решения [#6-why-not-other-designs]

- **`[first, ..rest]` (Rust):** `..` уже означает «игнорировать остальные поля» в шаблонах структур, а `...` —
  это распаковка, знакомая всем по спискам.
- **`first :: rest` (ML / Haskell):** cons-шаблоны предполагают связные списки. Наши — массивы, где «остаток» —
  это представление, а средний и конечный случаи (`[...init, last]`) стоят столько же, сколько начальный.
- **Отдельный `match` для списков:** решение было — один `switch` на всё.

## 7. Оставлено на потом (вернуться после появления проверки) [#7-left-for-later-revisit-after-the-checker-exists]

- **Запомнить для будущих версий: `sink` в шаблонах списков.** Потребляющие шаблоны списков (`switch sink xs { case [a, ...rest]: ... }`, где `a` и `rest` становятся
  собственными). Возможно, когда `sink` для владеющего списка сможет безопасно отдавать части; сначала нужна проверка.
- **Шаблоны для словарей и множеств.** Поиск остаётся `map.get(k)`, возвращающим `option`, который сопоставляется обычным образом.
- **Шаблоны для итераторов**, которые нельзя сохранить и у которых нет длины.

## Решения черновика 1 [#decisions-from-draft-1]

- **LP1** `...` — маркер остатка (голый — игнорировать, `...name` — связать), не более одного в шаблоне.
- **LP2** `rest` — временное представление-срез; `copy rest` создаёт собственный список.
- **LP3** Режимы доступа стоят перед привязкой: `[inout first, ...inout rest]`.
- **LP4** `sink` для элементов шаблона списка в v1 не разрешён. Остаётся в списке того, к чему стоит вернуться (раздел 7).
- **LP5** Массивы фиксированного размера можно разбирать в обычных объявлениях; списки используют `guard ... is` или `if ... is`.
- **LP6** (a) `if x is pattern` в построителе приносит свои имена в результат (закрывает B5). (b) Присутствующий вариант
  `option` сопоставляется как `some(v)` — слово только для шаблонов, как `ok` и `err`; значения по-прежнему пишутся «голыми».
- **LP7** Текст получает оба варианта: литеральные случаи и шаблоны списков над `char` с остатком `str`.
- **LP8** Маркер остатка может стоять посередине.
