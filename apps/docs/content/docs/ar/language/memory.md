سؤالان عن الذاكرة تركتهما الصفحات السابقة مفتوحين: مصفوفة من البنى (array of structs) مقابل بنية من المصفوفات (struct of arrays)، والأنواع الخطية.

## 1. أين نحن [#1-where-we-are]

القيم لها مالك. المعامل `sink` أو `move` يسحب القيمة من مالكها، و`deinit` يعمل عندما تخرج القيمة من النطاق، ولا يمكن استخدام قيمة منقولة مرة أخرى. بلغة نظرية الأنواع هذا **أفيني** (affine): يجوز استخدام القيمة مرة واحدة على الأكثر، ويجوز أيضًا التخلص منها.

## 2. AoS و SoA [#2-aos-and-soa]

- **AoS** (array of structs، مصفوفة من البنى): تُخزَّن حقول كل عنصر معًا. هكذا تُخطِّط C المصفوفة `point[]`، وهذا ما يعنيه `[point]` في هذه اللغة. إنه التخطيط المناسب عندما تستخدم العناصر كاملة، ويطابق C في التشغيل البيني.
- **SoA** (struct of arrays، بنية من المصفوفات): مصفوفة واحدة لكل حقل. إنه التخطيط المناسب عندما تلمس الحلقة حقلًا واحدًا (كل قيم `x`) لأن البيانات تكون متراصة في الذاكرة المخبئية (cache) وتُحوَّل جيدًا إلى عمليات متجهية (vectorise).

**اقتراح.** الافتراضي هو AoS لأنه متوقَّع ومتوافق مع C. أما SoA فاختياري، كنوع مجموعة له الواجهة نفسها:

```
var points: soa<point> = soa []
points.push!(point { x: 1.0, y: 2.0 })

points[0].x                  // reads through a view of element 0, same code as a list
points.x                     // the whole x column as a read-only [float]: a SIMD-friendly slice
for inout p of points { p.x += 1.0 }
```

لأن المراجع مؤقتة (من الدرجة الثانية) في ظل دلالات القيمة، فإن `points[i]` هو دائمًا عرض (view) يعيش لجملة واحدة، لذا يمكن تغيير التخطيط الكامن خلفه دون تغيير أي شيفرة تستخدمه. هذه ميزة حقيقية مقارنةً باللغات التي يمكن فيها لمراجع العناصر أن تفلت. و`soa<point, 8>` هو المتغير المقسَّم إلى كتل (AoSoA) الذي يجمع 8 عناصر في كل كتلة بحسب عرض المتجهات.

أما مصرِّف يختار التخطيط بنفسه فيبقى في قائمة «لاحقًا»، لأنه يحتاج إلى تحليل للبرنامج بأكمله.

الصف (tuple) ذو الحجم الثابت `(A, B; N)` هو تخطيط متداخل، أي نكهة AoS للأنواع المختلطة. و`soa<T>` هو عكسه، وبذلك يغطي الاثنان الطرفين معًا.

## 3. الأنواع الخطية [#3-linear-types]

الأنواع الأفينية تسمح بالتخلص من القيمة بصمت. أما الأنواع **الخطية** فتمنع ذلك: يجب استهلاك القيمة مرة واحدة بالضبط. هكذا تتحول عبارات مثل «يجب إغلاق هذا الملف» و«يجب تأكيد هذه المعاملة أو التراجع عنها» و«يجب إعادة هذا الإذن» إلى أخطاء في وقت التصريف. لا تملك Rust أنواعًا خطية (تحذيرات فقط)، بينما تملكها Austral وHylo.

**اقتراح.** نحن نملكها تقريبًا بالفعل. نضيف مُعدِّلًا اختياريًا:

```
linear struct transaction { ... }

fn commit(sink t: transaction) -> void ! db_error { ... }
fn rollback(sink t: transaction) { ... }

fn work() -> void ! db_error {
    const t = begin()?
    do_things(t)               // read-only use, fine
    t.commit!!()               // consumed. Forgetting this is a compile error.
}
```

- يجب استهلاك القيمة الخطية في كل مسار، بما في ذلك حالات الإرجاع المبكر و`?`. ويذكر المصرِّف أي مسار نسيها.
- النوع الخطي لا يملك `deinit` لأنه لا يمكن التخلص منه ضمنيًا أبدًا.
- `sink` تعني أصلًا «يسحب القيمة»، و`!!` تعلِّم أصلًا الاستدعاء المستهلِك، فلا حاجة إلى صياغة جديدة عند موضع الاستدعاء.
- الشيفرة العامة (generic) تحتاج إلى عناية: افتراضيًا يجوز التخلص من معاملات النوع، فلا يمكن أن يكون `T` نوعًا خطيًا إلا إذا نصَّ القيد على ذلك (`<T: linear>`). أبقِ هذا الباب مفتوحًا عند تصميم مدقق الأنواع، ولا تثبِّت في أي مكان أن «كل نوع يمكن التخلص منه».

**المراحل.** الإصدار 1 أفيني مع تحذير `@must_use`. تصل الأنواع `linear` الحقيقية بعد وجود مدقق الأنواع، لأنها تغيّر قواعد الأنواع العامة. الكلمة `linear` محجوزة من الآن (كلمة مفتاحية مرنة).

## منجز: soa [#built-soa]

يعمل `soa<T>` لبنية `T` كما وُصف أعلاه (انظر IR24 في `ir.md`): `soa []` و`soa [a, b]` و`push!` و`pop!` و`insert!` و`remove!` و`clear!` و`len` و`points[i]` و`points[i].x` و`points.x` وحلقات `for` و`for inout` و`copy` و`==` و`print`. الصيغة المقسَّمة `soa<T, N>` مقبولة وتتصرف بالطريقة نفسها؛ أما تخطيط ذاكرتها المقسَّم فمتروك للواجهة الخلفية.

## القيم المؤقتة [#temporaries]

القيمة التي تُنشأ ولا يُطلق عليها اسم أبدًا (نتيجة دالة تتجاهلها، أو الكائن الكامن خلف `make_dog("a").name`، أو وسيط يُبنى في موضعه) تُدمَّر **في نهاية جملتها**، بترتيب عكسي لترتيب إنشائها. وإذا أخذها شيء ما (متغير، حقل، معامل `sink`، `return`) فإن المالك الجديد هو من يدمّرها لاحقًا. يمسك المصرِّف هذه الدفاتر أثناء بناء الشيفرة (دفتر الحسابات، IR22)؛ ولا توجد كلفة وقت تشغيل في الشيفرة المتسلسلة تتجاوز ما تدفعه المتغيرات أصلًا.

## قرارات المسودة 1 [#decisions-from-draft-1]

- **M1** AoS هو التخطيط الافتراضي. و`soa<T>` هي المجموعة الاختيارية، مع `soa<T, 8>` كمتغير مقسَّم.
- **M2** الوصول إلى العمود (`points.x`، وهو `[float]` للقراءة فقط) مُعتمد.
- **M3** التخطيطات التي يختارها المصرِّف تبقى تحسينًا لاحقًا.
- **M4** `linear` مُعدِّل اختياري مجدول بعد مدقق الأنواع. الكلمة محجوزة من الآن ككلمة مفتاحية مرنة.
